D. Création d’un émulateur
Un émulateur sert à émuler un appareil Android particulier, afin de développer une application pour divers
types d’appareil (téléphone ou tablettes, avec différentes tailles d’écran...) sans pour autant avoir besoin de
tous les posséder. Dans le cadre de ce module, l’émulateur pourra vous servir également à travailler lorsque
vous n’avez pas accès aux téléphones. Pour cela, nous allons créer un émulateur dont ayant des caractéristiques
similaires à celles d’un téléphone.
a.
Cliquer sur l’icône avec un rectangle violet « AVD Manager » (pour « Android Virtual Device »);
b.
Choisir « Create Virtual Device... », puis choisir parmi les phones l’architecture prédéfinie la plus
proche de votre téléphone (ou à défaut, un Nexus 5X)
c.
Lancer l’émulateur ;
E. Découverte de l’application
Regarder ce que fait l’application. Vous l’aurez constaté, pour l’instant, elle se contente d’afficher « Hello
world! ». Nous allons présenter les différents composants de cette application, qui feront ensuite chacun l’objet
de différents TPs.
a.
Dans le menu à gauche du studio, déplier le répertoire « app ». Il contient trois sous-répertoires :
Le répertoire manifests contient les fichiers décrivant l’architecture de l’application ;
Le répertoire java contient les fichiers source Java ;
Le répertoire res contient tout ce qui a trait à l’interface graphique de l’application.
b.
Consulter le fichier AndroidManifest.xml du répertoire manifests. Il décrit l’architecture de
l’application : son nom, son thème, les activités qu’elle contient (il n’y en a pour l’instant qu’une).
Ce fichier doit être édité lorsqu’on ajoute de nouvelles activités, à la main ou automatiquement via
l’utilisation des fonctionnalités d’Android Studio.
Consulter le fichier MainActivity.java du répertoire java. Il s’agit d’une classe Java implantant
l’activité, contenant la méthode onCreate. Cette methode est appelée à la création de l’activité.
Un de ses rôles est de démarrer l’interface graphique, via l’appel à la méthode setContentView ;
c.
Ouvrir le fichier activity_main.xml du répertoire res/layout. Il décrit l’interface graphique de
l’activité. Android Studio propose deux vues pour lire ce fichier :
o
L’onglet « Split » ou « code » affiche simplement le contenu du fichier, à savoir du
XML décrivant les diverses couches de l’interface, ainsi qu’une prévisualisation du
résultat (pour laquelle on peut choisir différents appareils, notamment notre émulateur);

Regarder le contenu XML : l’interface contient une seule couche de type RelativeLayout, elle-même

F. Attribution d’écouteurs aux boutons
Android offre deux possibilités :
Soit vous déﬁnissez l’attribut android:onClick et vous créez une méthode dans l’activité concernée.
Soit vous déﬁnissez l’activité elle-même en tant qu’écouteur, et voici la démarche à faire : Il faut éditer
la méthode onCreate de l’activité concernée et rajouter des instructions comme celles-ci.
Button btn1 = findViewById(R.id.btn1);  
btn1.setOnClickListener(this);
Cela consiste à attribuer this en tant qu’écouteur des clics sur le bouton concerné.
AndroidStudio vous signalera que l’activité this n’est pas un écouteur correct. Il suﬃt simplement qu’elle
implémente l’interface OnClickListener.
Ensuite, AndroidStudio signalera qu’il manque la méthode exigée par l’interface OnClickListener c’est à dire
onClick(View v). Son paramètre est une vue v d’un type général View, mais en réalité, ce sera un Button.
