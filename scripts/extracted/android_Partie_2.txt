AndroidManifest.xml est le fichier de configuration XML de l’application.
Il ne doit pas être renommer, ni déplacer
C’est un fichier indispensable à chaque application qui décrit entre autres :
le point d’entrée de votre application (quel code doit être exécuté au démarrage de
l’application) ;
Le nom de l’application, son icone, son package (l’identifiant unique sur le Play
Store)
Définit les composants qui constituent ce programme ;
les permissions nécessaires à l’exécution du programme :
Les permissions matérielles (accès à l’appareil photo, GPS, ...).
Les permissions d’interactions entre les applications (accès à Internet, répertoire
téléphoniques, galerie des photos…)

<application> : un seul et unique noeud application
<uses-permission> : l’utilisateur se verra demander l’autorisation d’utiliser l’ensemble
des fonctions liées à ces permissions
<activity> : Déclare une activité présentée à l’utilisateur
<service> : Déclare un composant de l’application en tant que service.
<receiver> : Déclare un récepteur d’objets Intent. Cet élément permet à l’application de
recevoir ces objets alors qu’ils sont diffusés par d’autres applications ou par le
système.
<provider> : Déclare un fournisseur de contenu qui permettra d’accéder aux données
gérées par l’application.

Présentation d’une Activité
Une activité est un composant d’une application qui fournit un écran avec lequel
l’utilisateur peut interagir.
Une application contient plusieurs activités
Une activité = Contexte + une Interface graphique
Question : que se passe-t-il si on reçoit un SMS alors que l’utilisateur manipule
l’application mobile?
L’activité de l’application mobile passe d’un état à un autre.
C’est le Cycle de Vie d’une Activité

Quand l’utilisateur reçoit un appel téléphonique, l’activité courante passe dans l’état
OnPause ensuite, Stopped, lorsque l’appel téléphonique est terminé, cette activité
revient dans Started puis Resumed.
Quand une activité passe d’un état à un autre, le framework Android appelle les
méthodes de transition correspondantes :
void onCreate (Bundle savedInstanceState) : obligatoire
void onStart ()
void onResume ()
void onRestart ()
void onPause () : recommandée
void onStop ()
void onDestroy ()
