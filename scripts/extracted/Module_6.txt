===== PAGE 2 =====
Définition d’un paquet logiciel

Un paquet logiciel est une archive contenant tous les éléments nécessaires à
l’installation d’un programme.
Il contient :
-
Les fichiers binaires exécutables (le programme compilé)
-
Les bibliothèques nécessaires à son fonctionnement
-
Les fichiers de configuration
-
Les scripts de post-installation / suppression (pour automatiser certaines
tâches)
-
Les métadonnées : nom, version, dépendances, architecture, mainteneur, etc.
NB: un paquet n’est pas un simple fichier exécutable, mais une structure complète
assurant une installation cohérente et traçable sur le système.

===== PAGE 4 =====
Paquet binaire

Un gestionnaire de paquets est un outil qui permet d’installer,
mettre à jour et supprimer des logiciels automatiquement, sans
passer par les étapes manuelles de compilation.

Objectif:
Simplifier la vie de l’administrateur en gérant :
-
Les dépendances (bibliothèques nécessaires)
-
Les mises à jour
-
Les signature de sécurité
-
La désinstallation propre

===== PAGE 7 =====
Formats standards (.deb et .rpm)

Formats les plus répandus :
-
.deb →Debian, Ubuntu, Linux Mint, etc.
-
.rpm →Red Hat, CentOS, Fedora, openSUSE

Ces formats ne sont pas interchangeables

Chaque format dispose de ses outils dédiés:
-
.deb →dpkg, apt
-
.rpm →rpm, dnf, yum

===== PAGE 8 =====
Cycle de vie d’un paquet

Téléchargement
→Récupération du paquet depuis un dépôt ou une source externe(apt
download, wget, etc)

Installation
→Décompression et copie dans des fichiers dans le système (apt install, dnf install,
rpm -i)

Mise à jour
→Remplacement propre d’une version par une autre (apt upgrade, dnf update)

Suppression /purge
→Désinstallation du paquet et de ses fichiers associés (apt remove, rpm - e)
Objectif : assurer une gestion cohérente, stable et traçable des logiciels installés.

===== PAGE 21 =====
Sécurité & Intégrité : Vérification
d’intégrité du code source

Objectif: S’assurer que le fichier télécharger n’a pas été altéré ou
corrompu

Méthodes:
-
Chaque projet open source publie une empreinte(Hash): SHA256 ou
MD5
-
On compare la somme du fichier télécharger avec celle fournie sur
le site officiel
----------Code source : utilisé avant la compilation
---------- Paquet binaire elle est vérifie automatiquement par le gestionnaire
-
Si les valeurs correspondent, le fichier est authentique et intact.
Sinon, ne jamais l’exécuter ni le compiler.

===== PAGE 22 =====
Sécurité & Intégrité : Vérification
de la signature GPG

Objectif:
S’assurer que le paquet provient bien du fournisseur légitime (authenticité).

Principe:
Le développeur signe le paquet avec sa clé privée GPG,
et l’utilisateur vérifie la signature avec la clé publique du projet.
Cas d’usage:
-
Il (l’utilisateur)doit importer la clé public du fournisseur(développeur) afin de vérifier
la signature du paquet
-
Pour un paquet source: souvent .asc ou sig accompagant le code
-
Pour un paquet binaire: apt, dnf et zypper vérifier autmatiquement les clés GPG

===== PAGE 23 =====
Sécurité & Intégrité : Importance
en environnement professionnel

Pourquoi c’est crucial:
Protection contre les paquets compromis(supply chain attrack)

===== PAGE 24 =====
Gestion de base-niveau

Gestion bas-niveau (low-level package management)
La gestion de bas niveau permet d’installer, supprimer ou interroger
directement des paquets individuels
Ne gére pas automatiquement les dépendances

RPM (Red Hat Package Manager) : utilisé sur Red Hat, CentOS,
Fedora.

DPKG (Debian Package) : utilisé sur Debian, Ubuntu.
Exemple :

rpm -i package.rpm

dpkg -i package.deb

===== PAGE 25 =====
Gestion de haut-niveau

Gestion haut-niveau (High-Level Package Management)
La gestion de haut niveau automatise l’installation, la mise à jour et la suppression des
paquet avec toutes leurs dépendances
Elle utilise les dépôts officiels pour récupérer les paquets
Exemples de gestionnaires
APT(Debian, Ubuntu)
apt update
# mettre à jour la liste des paquets
apt install nginx
# installer un paquet avec dépendances
apt upgrade
# mettre à jour tous les paquets
YUM/ DNF (Red Hat, CentOS, Fedora
yum install httpd
dnf update
yum remove package

===== PAGE 30 =====
Automatisation et scripts

Script Bash d’installation automatique :
#!/bin/bash
sudo apt update -y
sudo apt install -y curl vim
sudo apt remove -y nano
apt list --installed > liste_paquets.txt
Utile pour audit, documentation ou sauvegarde de l’état des paquets.

Sauvegarde de la liste des paquets :
dpkg --get-selections > sauvegarde.txt
Permet de connaître l’état exact des paquets gérés par dpkg

Restauration :
dpkg --set-selections < sauvegarde.txt # restaurer la liste des paquets depuis la sauvegarde
sudo apt-get dselect-upgrade
#appliquer les changement avec APT, synchroniser le système

===== PAGE 31 =====
Automatiser les mises à jour
avec Cron

Automatiser les mises à jour hebdomadaires :

Exemple de tâche cron :
sudo crontab –e
# Ajoutez la ligne suivante :
0 2 * * * /usr/bin/apt update && /usr/bin/apt upgrade –y
➡Exécute les mises à jour tous les jours à 02h00.

Avantage :
Maintenance automatisée du système
