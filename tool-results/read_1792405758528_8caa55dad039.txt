   454→Les protocoles de communication IoT sont des règles et standards permettant aux 
   455→dispositifs (capteurs, actionneurs, passerelles, etc.) d’échanger des données de manière 
   456→fiable et sécurisée, malgré des contraintes de ressources (énergie, bande passante, 
   457→puissance de calcul).
   458→Enjeux
   459→• Faible consommation d’énergie (ex : capteurs sur batterie).
   460→• Latence réduite (temps réel).
   461→• Fiabilité dans des environnements perturbés.
   462→• Sécurité des données (chiffrement, authentification).

   694→VI. Protocoles de communication série pour périphériques     
   695→(UART, SPI, I2C, 1-Wire et CAN)
   696→VI.1 Définitions
   697→• Communication série vs parallèle :
   698→o Série : Transmission bit par bit sur un seul fil (ex : UART).
   699→o Parallèle : Transmission simultanée sur plusieurs fils (ex : bus PCI).
   700→• Avantages de la communication série :
   701→o Coût réduit, simplicité de câblage, adaptée aux longues distances.

   706→VI.2 Protocoles asynchrones (sans horloge)
   707→UART (Universal Asynchronous Receiver/Transmitter)
   708→• Principe 
   709→o Asynchrone : Pas de signal d’horloge partagé.
   710→o Trame : Bit de start (0), données (5-9 bits), bit de parité (optionnel), bits de stop (1).
   711→o Baud rate : Vitesse de transmission (ex : 9600, 115200 bauds).
   712→• Utilisation: Communication entre microcontrôleurs, modules GPS, Bluetooth.
   713→• Avantages : Simple, universel.
   714→• Inconvénients : Pas de détection d’erreur (sans parité), distance limitée.
   715→RS-232 : Standard industriel pour UART (niveaux de tension ±3 à ±15V).
   716→RS-485 : Communication différentielle pour longues distances (jusqu’à 1200m).
   717→VI.3 Protocoles synchrones (avec horloge)
   718→1. SPI (Serial Peripheral Interface)
   719→• Principe 
   720→o Synchrone : Horloge partagée (SCK).
   721→o Périphérique maître/esclave : Fils : MOSI (Master Out Slave In), MISO (Master In 
   722→Slave Out), SS (Slave Select).
   723→o Mode de communication : Full-duplex (données bidirectionnelles simultanées).
   724→• Utilisation:
   725→o Mémoires (EEPROM, Flash), écrans LCD, capteurs haute vitesse.
   726→• Avantages : Débit élevé (jusqu’à 100 Mbps), flexible.
   727→• Inconvénients : Nombreux fils (4 minimum), pas de gestion native des erreurs.

   732→VI.3 Protocoles synchrones (avec horloge)
   733→2. I2C (Inter-Integrated Circuit)
   734→• Principe 
   735→o Synchrone : Horloge partagée (SCL) et données bidirectionnelles (SDA).
   736→o Adressage : 7 ou 10 bits pour identifier les esclaves.
   737→o Structure de trame : Start bit → adresse esclave → données → stop bit.
   738→• Utilisation:
   739→o Capteurs (température, pression), RTC (Real-Time Clock).
   740→• Avantages : 2 fils seulement et multi-esclaves.
   741→• Inconvénients : Débit modéré (400 kHz en standard, 5 MHz en Ultra Fast Mode).
   742→Résistance: Améliore l’impédance et donc la longueur de la ligne
   743→VI.4 Protocoles spécialisés
   744→1. 1-Wire
   745→• Principe 
   746→o Single-wire : Communication + alimentation sur un seul fil (DQ).
   747→o Adressage unique : Chaque périphérique a une ROM ID 64 bits.
   748→• Utilisation:
   749→o Capteurs Dallas (DS18B20), systèmes de sécurité.
   750→• Avantages : Câblage minimal, idéal pour les réseaux de capteurs.
   751→• Inconvénients : Débit très lent (15 kbps), complexité logicielle.

   756→VI.4 Protocoles spécialisés
   757→2. CAN (Controller Area Network)
   758→• Principe 
   759→o Réseau différentiel (CAN_H et CAN_L) pour environnements bruyants.
   760→o Gestion des collisions : Priorité des messages par ID.
   761→• Utilisation: Automobile, industrie (automates).
   762→• Avantages : Robustesse, tolérance aux pannes.
   763→• Inconvénients : Complexité matérielle.
